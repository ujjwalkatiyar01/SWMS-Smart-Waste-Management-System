## 3. Adapter contract

```ts
type AiResult = {
  category: 'wet' | 'dry' | 'biomedical' | 'hazardous' | 'e_waste' | 'mixed_uncertain';
  confidence: 'high' | 'medium' | 'low';
  hazard: boolean;
  visible_items: string[];
  reason: string;           // one short sentence
};
classifyWastePhoto(jpeg: Buffer, opts: { timeoutMs: number }): Promise<AiResult>
```

**Instruction to the model (summary, 05 §2):** classify only what is visible; prefer `mixed_uncertain` when unsure or mixed; `hazard: true` for syringes, needles, blood-stained material, medicines, chemicals, batteries, broken glass or unknown containers; never guess location, people or identity; answer only in the JSON format.

## 4. Request flow

```
1. Frontend sends the resized JPEG to /api/ai/classify (logged-in users only).
2. Server: ai_quota_left() as the user → over limit (demo 20/user/day, 200/org/day) → "AI suggestion not available right now".
3. Server: re-encode with sharp (no metadata); photo is NOT stored.
4. classifyWastePhoto() with timeout 8 s (demo) → zod check → invalid = mixed_uncertain.
5. Server inserts ai_runs with the service-role client (user_id = caller); returns suggestion + ai_run_id.
6. Frontend: high/medium → pre-select; low → "uncertain", not pre-selected; hazard → red notice.
7. On submit, create_report links the ai_run_id; the hazardous deadline applies only if the final category is kept as biomedical/hazardous.
Error / timeout / limit at any step → manual choice; submit never blocked.
```

## 5. Privacy and cost

- `GEMINI_API_KEY` is server-only.
- Sent: only the EXIF-stripped, resized photo and the instruction. **No names, emails, phones or addresses.**
- **Free-tier content may be used to improve Google's products [Doc] → demo photos only.** Paid tier or another provider before real use.
- Limits vary by project and are shown in Google AI Studio [Doc]; our own daily caps protect the quota.

## 7. Testing (05 §9)

≥ 10 demo photos per category, including mixed piles and hazardous items; report per-category results and **hazard recall** (missed hazards matter most). Dashboard signal: how often a human changed the AI suggestion. These are demo measurements, not validated accuracy.

## 8. Risks

| Risk | Mitigation |
|---|---|
| Free-tier limits or outage | Timeout, daily caps, manual fallback, logged in `ai_runs` |
| Misclassification, especially hazards | Editable category, *uncertain* option, hazard recall measured |
| Users forging AI results | `ai_runs` written only by the server (tested, 06 S1) |
| Free-tier data use | Demo photos only |

### Implementation checkpoint 🆕 (2026-10-01)

### F14 text chatbot expansion 🆕 (user request, 2026-10-01)

The earlier “Only one feature calls an AI model” describes the approved A1–A8 scope at that time. F14 now explicitly adds a second model use: the SWMS bot. It uses the existing server-only `GEMINI_API_KEY` and Google Gen AI SDK, plus a separate `reserve_bot_run` quota reservation and `ai_runs.feature = 'chat'` audit entry. Public questions use deterministic user-facing guidance and make no provider call. Authenticated questions may send only retrieved, permission-scoped status summaries and selected workflow guidance. The model receives instructions to stay within those sources, disclose missing information, and ignore instructions inside retrieved content. It cannot call database mutations. A missing key, failed call, or exhausted quota returns the grounded local answer. Live model quality requires verification after a key is configured. No earlier text was removed.

Privacy refinement 🆕: account-specific status questions are answered on the server without a provider call. Private row summaries are never sent to Gemini. Only signed-in general-help questions can use the model; the UI asks users not to include personal details. This narrows the earlier proposed provider context while preserving its text for audit history.

### Photo analyzer implementation checkpoint — continued

The report form and awareness helper now call `/api/ai/classify`; the route authenticates the user, re-encodes a JPEG with Sharp to remove metadata, reserves a daily quota slot with `reserve_ai_run`, calls the server-only Google Gen AI SDK with an 8-second timeout, validates the JSON with zod, and logs the result or failure in `ai_runs`. High/medium suggestions may preselect the report category; low/uncertain results and any error leave manual choice available. Model `gemini-3.5-flash-lite` was selected after checking Google's [model list](https://ai.google.dev/gemini-api/docs/models) and [free-tier pricing](https://ai.google.dev/gemini-api/docs/pricing) on 2026-10-01. The local `GEMINI_API_KEY` is empty, so live classification and accuracy/hazard-recall checks remain unverified. No photo is sent to Google without that key.
